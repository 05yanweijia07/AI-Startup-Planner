# Business Plan Generation Core Workflow

## Module metadata

- **Module ID:** BPG-001
- **Category:** Business-plan generation
- **Version:** 1.0.0-draft
- **Status:** Initial core Reference
- **Triggers:** Business plan, pitch deck, integrated plan, investor brief
- **Exclusions:** A single focused question without a document request
- **Dependencies:** Portable control rules; current project state; relevant market, strategy, financial, and operations outputs

## Purpose

Assemble existing project knowledge into a clear audience-appropriate deliverable without disguising gaps or changing the underlying evidence.

## Workflow

1. **Confirm the brief.** Identify audience, purpose, format, length, language, and whether the document is internal, lender-facing, investor-facing, or operational.
2. **Inventory source material.** Read current project state, confirmed decisions, evidence, assumptions, and latest analyses. Identify missing, stale, or contradictory inputs.
3. **Build the outline.** Select only sections appropriate to the brief. Common sections include summary, problem/customer, market, offer, model, go-to-market, operations, team, financial scenarios, risks, and milestones.
4. **Draft from authoritative inputs.** Preserve units, periods, definitions, and source distinctions. Mark assumptions and projections as such; do not invent traction, credentials, customer validation, partnerships, or approvals.
5. **Integrate and reconcile.** Check that target customer, offer, price, channel, capacity, and financial assumptions agree across sections.
6. **Review for the audience.** Remove repetition, define terms, disclose material uncertainties, and ensure the requested format is complete.
7. **Deliver and track.** Save only to the intended authorized project location. Register the deliverable and its sources when project persistence is available.

## Output requirements

The artifact should state its purpose and date/version when known; clearly separate facts, estimates, assumptions, and recommendations; cite research sources where used; identify unresolved items; and end with practical next actions where appropriate.

## Quality and risk checks

- Every material claim is traceable to a source, decision, or clearly labeled assumption.
- Financial figures use consistent periods, currency, and scenario labels.
- No unpassed gate is implied to have passed through polished wording.
- The document answers its audience's likely decision questions without overstating certainty.
- File creation or external sharing is claimed only after it actually occurs and is authorized.

## Integration

The plan is a derived deliverable, not a second authoritative project database. Register its source records and mark it stale when a material dependency changes.
